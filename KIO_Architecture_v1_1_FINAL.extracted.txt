§1 · Executive Summary & Philosophy
What KIO Is
Python-native autonomous agent runtime
Cloud-inference orchestration layer (brain cloud, body
local)
Resource-disciplined tool execution coordinator
Personal productivity OS: single user, single machine
What KIO Is NOT
✗ Chatbot or conversational assistant
✗ Local LLM runtime
✗ Multi-agent swarm
✗ LangChain wrapper
✗ AGI system
✗ Framework-heavy ecosystem
Core Tenets (Immutable)
T1 · Cloud Brain, Local Body
All reasoning via cloud LLM API. KIO never loads a local language model. Local
process = orchestration, execution, memory, I/O only.
T2 · Everything Through Core
Brain
No module executes autonomously. Every execution path routes through Core
Brain. No sidechannels, no bypass paths.
T3 · Lazy is Law
Any module >10 MB not needed at startup is lazy-loaded on first use, unloaded
after. Idle baseline: <120 MB.
T4 · Explicit Over Implicit
Tool contracts are typed. Side effects declared. Destructive ops require explicit
confirmation.
T5 · Stability Over Features
Stable Gate N > broken Gate N+2. Gates are locked until prior gates pass all tests.

§2 · Architecture Issues Found (v1.0 → v1.1)
10 issues identified in nanoscale audit pass. All resolved in v1.1.
I-01
MEDIUM
ThreadPoolExecutor thread timeout absent
PROBLE
M
max=2 threads declared but no timeout on submitted tasks. Blocked thread holds slot indefinitely.
Long-running CPU tool can starve all other threaded ops.
FIX
Add asyncio.wait_for wrapper + thread-level timeout via concurrent.futures.TimeoutError handling.
I-02
HIGH
EventBus maxsize=100 → async deadlock under load
PROBLE
M
If observer burst fires >100 events before dispatch loop drains, publish() coroutine blocks. Under high
filesystem activity this can stall Core Brain's async loop.
FIX
Raise maxsize to 500. Add drop-oldest policy with logged warning instead of blocking publisher. Non-execution
events must never block orchestration.
I-03
MEDIUM
Plugin max=1 limit prose-only, not enforced
PROBLE
M
Plugin simultaneous limit stated in text but no code contract shown. Runtime will silently allow second plugin
load.
FIX
Add hard guard in PluginManager.load() — reject with PluginLimitError if count >= 1 in v1.
I-04
HIGH
ResourceGuard polling interval 60s — too slow for spike prevention
PROBLE
M
Heavy tool (OCR, browser) can load and consume 80+ MB in under 5 seconds. 60s poll catches it 55s too
late.
FIX
Add pre-load RAM check in ObserverManager.load() and PluginManager.load() before every lazy-load. Check
current RAM + module budget vs HARD_LIMIT before allowing load.
I-05
MEDIUM
Verifier confidence threshold undefined
PROBLE
M
VerificationReport.confidence is 0.0–1.0 but no floor value defined for 'triggers replan'. Verifier behavior is
ambiguous.
FIX
Define REPLAN_CONFIDENCE_FLOOR = 0.6. Any report with confidence < 0.6 AND overall_success=False
forces replan.
I-06
HIGH
Context compression path breaks in DEGRADED mode
PROBLE
M
Context compression (summarization) is an LLM call. When LLM API is unreachable (DEGRADED state),
compression fails silently — context window can grow unbounded.
FIX
In DEGRADED mode: disable summarization. Use hard truncation (drop oldest turns) as fallback. Log warning.
Resume summarization when LLM restored.
I-07
MEDIUM
Startup LLM check → DEGRADED at boot not modeled
PROBLE
M
Startup step 7 verifies LLM connectivity but state machine shows INIT → READY only. If LLM is down at
boot, the transition path is undefined.
FIX
Add INIT → DEGRADED path. Startup sequence: if LLM check fails → enter DEGRADED immediately → notify
user → continue with local-only tools.

I-08
LOW
Observer idle timeout hardcoded, not configurable
PROBLE

OBSERVER_IDLE_TIMEOUT referenced as default 60s but not included in config.json schema. Operators

I-09

PROBLE
M
KIOWatchdog calls self.attempt_restart() after 3 missed beats but this method is never defined in the

FIX
Define restart procedure: (1) flush in-flight ops with 5s grace, (2) cancel all asyncio tasks, (3) re-run startup

On every write? At session end? Never?
FIX
Run pruning as async background task every 30 minutes. Also prune on session start before loading context. Use
VACUUM after large prune to reclaim SQLite space.

§3 · Corrections Applied in v1.1
Summary of all architectural changes from v1.0 to v1.1:
✓ Thread Timeout Enforcement
Added asyncio.wait_for() wrapper around ThreadPoolExecutor tasks. Default
per-thread timeout: OPERATION_TIMEOUT (30s). On timeout: CancelledError
logged, step marked failed, retry logic engages.
✓ EventBus Overflow Policy
maxsize raised 100 → 500. Blocking publish replaced with drop-oldest policy: if
queue full, oldest event dropped with WARN log. Execution-critical path never
stalls on notification backpressure.
✓ Plugin Limit Hard Guard
PluginManager.load() now raises PluginLimitError if active_plugin_count >=
MAX_PLUGINS (1 in v1). Documented in PluginManager contract. Test added at
Gate 5.
✓ Pre-Load RAM Check
ObserverManager.load() and PluginManager.load() both call
ResourceGuard.check_capacity(module_ram_budget_mb) before loading. If
current_ram + budget > HARD_LIMIT: load rejected with RamBudgetError.
ResourceGuard 60s poll remains as audit; pre-load check handles spike
prevention.
✓ Verifier Confidence Floor
REPLAN_CONFIDENCE_FLOOR = 0.6 defined in verifier/verifier.py constants.
Replan triggered when: overall_success=False AND confidence < 0.6.
Documented in VerificationReport schema.
✓ DEGRADED Mode Context
Handling
Context compression (LLM summarization) disabled in DEGRADED state.
Fallback: hard truncation — drop oldest N turns to fit 4096 token budget. Logged
as WARN. Compression resumes automatically on LLM restore.
✓ Startup DEGRADED Path
State machine now includes INIT → DEGRADED transition. If LLM connectivity
check fails at startup step 7: state = DEGRADED, user notified via
Telegram+CLI, local-only tools remain available. Periodic retry (60s) attempts
restoration.
✓ Observer Timeout Config
observer_idle_timeout_s added to config.json schema. Default: 60. Range:
10–3600. Validated at startup. PLUGIN_IDLE_TIMEOUT similarly externalized
as plugin_idle_timeout_s (default 300).
✓ Watchdog Restart Procedure
attempt_restart() formally defined: (1) flush in-flight ops, 5s grace; (2) cancel all
asyncio tasks; (3) re-run startup sequence in-process; (4) on second consecutive
failure: sys.exit(1) — systemd service restarts process.
✓ Episodic Pruning Schedule
Pruning runs as async background task every 30 minutes via
asyncio.create_task. Also runs on session start before context load. After large
prune (>500 rows deleted): VACUUM executed. Execution log prune on same
schedule.

§5 · Core Brain Specification
Core Brain is the mandatory routing hub. Every execution decision passes through it. It is a router and coordinator — not an
implementer.
Responsibilities
Responsibility
Description
Session Management
Maintains active session state, user identity, context window
Intent Routing
Classifies incoming input → routes to planner or direct response
LLM Gateway
Single point of contact for all cloud LLM API calls
Context Evolution
Manages context sent to LLM (compression, injection, DEGRADED truncation)
Goal Tracking
Maintains active goals, sub-goals, completion states
Execution Control
Approves/rejects execution plans before they reach Executor
Memory Coordination
Reads/writes to Memory Manager — decides what to persist
Replanning
Detects failed plans → triggers replanning with updated context
What Core Brain Does NOT Do
✗Directly execute tools
✗Write to filesystem
✗Manage observer lifecycles
✗Handle authentication
✗Format output for channels
✗Store secrets or API keys

§18 · Final Engineering Rules (Permanent)
These rules govern all future KIO development. Violations require full architectural review.
MUST Always Follow
✓ Core Brain is the single execution router. No architecture that bypasses it is acceptable.
✓ observe → reason → plan → execute → verify → adapt loop is immutable. Steps cannot be skipped.
✓ RAM targets are hard constraints. Features that breach them are blocked, not deferred.
✓ Tool contracts are typed. No dynamic, untyped tool execution at any gate.
✓ Audit log is append-only. Never add deletion API.
✓ Gates are sequential. Gate N must be complete before Gate N+1 starts.
✓ Every lazy-load must call ResourceGuard.check_capacity() before loading.
✓ EventBus is notification-only. Never route execution through it.
✓ DEGRADED mode must handle gracefully. Never crash when LLM is unreachable.
✓ Watchdog attempt_restart() must always be implemented before Gate 6.
✓ Memory pruning must run on a schedule. Never rely on ad-hoc pruning.
✓ Verifier confidence floor (0.6) must be enforced. Never silently succeed a low-confidence plan.
MUST NEVER Add
✗Local LLM integration before v4 (hardware upgrade required)
✗LangChain, LlamaIndex, or any heavy framework
✗Vector database (ChromaDB, Qdrant, Weaviate) before v4
✗Multi-agent architecture or autonomous agent swarms
✗Always-on camera, persistent OCR, or always-on audio before v3
✗subprocess mesh for plugins (use subprocess isolation in v2+, not mesh)
✗eval() or exec() on user-controlled input — ever
✗Blocking EventBus publishers — use drop-oldest policy
✗Thread-per-observer model — use asyncio tasks
✗RAM-unchecked lazy-loads — always pre-check capacity
Architecture Drift to Prevent
■ Core Brain growing into an implementer (God class). Keep it a router.
■ Tool execution leaking outside Executor (shortcut calls, helper functions).
■ Memory system growing vector embeddings before v4.
■ Observer system accumulating always-on observers that weren't approved.
■ Plugin system allowing multiple simultaneous plugins before RAM budget expands.
■ EventBus being used for execution routing as 'temporary' measure.
■ Context window growing without compression or truncation enforcement.
■ Security layers being 'temporarily' skipped for development convenience.
KIO is buildable. Every component maps to a concrete Python module. No component requires hardware
beyond spec. No component requires a paid service beyond a cloud LLM API key (Gemini free tier sufficient for
development). What will kill it: gate skipping, framework temptation, RAM budget drift. Build Gate 0. Run the
tests. Check the RAM. Then and only then: Gate 1.
